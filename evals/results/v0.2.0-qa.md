# v0.2.0 QA: A/B Testing & CRO Coach

This review used synthetic requests. It is an independent model forward test and deterministic package/calculator verification, not a customer study, statistical certification or a guarantee across AI clients.

## Executed tasks

A separate evaluating agent loaded the skill and relevant references, answered these seven requests from [the evaluation set](../cases.json), and executed the helper for the two supported binary planning cases. The evaluator received the requests and skill without expected answers or a proposed bug. The maintainer inspected the actual responses and JSON outputs before publication.

| Request ID | Observed behavior | Assessment |
| --- | --- | --- |
| `small-audience` | Estimated 8,158 per group, 1,428 enrollment days plus seven follow-up days at 80 eligible people/week. Recommended a focused usability exercise; did not promise causal lift or require heatmaps. | Appropriate feasibility and alternative-evidence handling. |
| `planning-inputs` | Estimated 8,158 per group and six enrollment days plus seven follow-up days at 20,000 eligible people/week. | `pm-revenue-method` | Selected a mean-revenue approach with Welch as a candidate, requested revenue variation and mature per-user data including nonpayers, and kept sample unresolved. | Did not substitute purchase counts or use the binary calculator. |

Asked for renewal eligibility/window definition. | Did not count 25,000 sessions as independent workspaces, add an SDK or deploy. |
| `existing-result` | Treated the reported +6% as descriptive after opportunistic daily stopping; requested original plan/history and matching analysis before a defensible verdict. | No retroactive sequential-validity claim, invented corrected p-value or confirmed winner. |
| `multi-variant-endpoint` | Identified 12 treatment-versus-control endpoint comparisons, requested a confirmatory family and matching power/error-control design, and discussed Holm as one option. | Did not accept the first unadjusted p<0.05 or use the two-arm helper as a multi-arm planner. |
| `business-margin-readout` | Interpreted the supplied +0.6-point effect and +0.1 to +1.1 interval as positive versus zero while the +1-point business requirement remained unresolved. | Did not equate significance or MDE with proof of a minimum commercial benefit. |

No material guidance failure surfaced in these seven executions. The brief template was clarified to prompt an explicit precommitted action for an inconclusive result. Renewal eligibility and calendar coverage remain project-specific inputs rather than invented defaults.

## Deterministic verification

- All 12 existing calculator tests passed, including the published R benchmark, per-group rounding, follow-up/calendar boundaries, invalid input rejection, sparse expected-cell review and illustrative scenarios. The calculator code and formula did not change in this release.
- Skill metadata, local Markdown links, the bundled MIT license and UI invocation passed package validation. The Agent Skills quick validator also passed.
- Skills installer 1.9.1 found exactly one skill and copied it into a clean temporary project for Codex. All nine installed skill files matched the source; both new references were present. The installed helper returned 8,158 per group and the 13-day arithmetic readout for the supported high-traffic case.
- Local environment: Python 3.14.6 and Node.js 26.5.0. CI retains Python 3.9, 3.11 and 3.13 checks; see the matching [Actions runs](https://github.com/Atticus-Li/first-ab-test/actions) for independent CI status.

## Discovery and publication checks

The README now identifies A/B testing, CRO, the intended users and concrete tasks in its title and opening. The skill description names actual use cases and its calculator boundary. The invocation/folder name stays `plan-first-ab-test`, preserving installation identity. UI metadata, the brief and the sample plan use the current display name.

Repository description and relevant topics support discovery on GitHub; they are not evidence of search rankings or adoption. The package credits Atticus Li's original synthesis and links to original statistical sources. It does not promise that AI systems will cite a source. GitHub controls its page-level metadata, and search engines control indexing and rankings.

## Coverage limits

Only one independent model execution pass and one client's clean installation were observed. The evaluations did not run live experiments, validate a customer's instrumentation, use real revenue data or compute an unsupported results analysis. No cross-client guarantee, conversion improvement, traffic gain or user demand was established. The helper remains a narrow fixed-horizon binary sample planner, not a universal statistics engine.
